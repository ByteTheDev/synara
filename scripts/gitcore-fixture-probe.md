# GitCore Windows fixture diagnostics

The original exact feature `a1b087d984a39cf9df936d5da9465db9e7679600` executed all 144 canonical GitCore cases in run `38178926396`: Ubuntu 144 passed, Windows 132 passed and 12 failed, with both complete source guards passing. The managed-link cases passed. These five bounded, synthetic Git experiments investigate fixture prerequisites only: LF checkout bytes, executable-index mode, a literal numeric-colon index entry, a trailing-space untracked filename, and filesystem-monitor command startup. They do not change or rerun the 144-case suite, and they do not diagnose the separate status-latency assertion or temporary-directory cleanup failure.

Fresh Ubuntu and Windows jobs compare original setup with candidate setup. The candidates use repository-local LF policy, explicit executable index mode, an index-only numeric-colon fixture with `core.protectNTFS=false` limited to that one insertion, repository-local `core.protectNTFS=false` only in the isolated trailing-space experiment, and a quoted slash-normalized fsmonitor command. No global Git setting changes. All exact LF, 100755, literal path/content and real marker assertions remain strict; candidate failures stay failures. The original phase is never converted to success because failure was expected.

The finite fsmonitor hook writes its real marker and exits. It does not impersonate the original infinite hook or prove production deadline/teardown behavior. The Git commands use owned synthetic directories only and never fetch/push or read a user's repository. The synchronous utility wrapper requests a 15-second root timeout and records actual status, signal and process error; it makes no descendant-cleanup guarantee. The isolated job has a separate ten-minute limit. No test, application source, credential, global Git preference or main ref is modified. Source/driver identity, raw command results, cleanup, failures and every evidence byte hash are retained.

Git documents [explicit index insertion and executable-mode updates](https://git-scm.com/docs/git-update-index); those primitives preserve index-content assertions on filesystems that cannot represent every Git path or POSIX execute bit. Actual Windows observations, independent review and the unchanged full production suite are required before any fixture repair is published.
